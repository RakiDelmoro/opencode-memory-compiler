### Session (16:45) - Database Connection Pooling

**Context:** Investigating connection pool issues in production

**Key Exchanges:**
- User reported "too many connections" error from Supabase
- Assistant explained connection pooling best practices
- Explored using `pgbouncer` vs Supabase's built-in pooling

**Decisions Made:**
- Will implement connection pooling at application level using `pgbouncer`
- Set max connections to 10 for the app pool
- Keep Supabase pool size at 20 to accommodate multiple services

**Lessons Learned:**
- Each serverless function instance creates its own pool
- Connection pooling prevents exhausting database connections
- Transaction pooling mode works best for short-lived serverless functions
